# Interface themes and the UI kit (loaded when working in components/ui, styles/themes)

Moved out of the root `CLAUDE.md` so it only loads when this folder is in play.
The root `CLAUDE.md` still holds the rules that apply everywhere.

## Interface themes (UI skins, not the card look)

- `components/ui-theme/` + `styles/themes/_themes.scss` + `styles/site-styles/_ui-kit.scss`: `data-ui-theme` on `<html>` (set before paint by `NO_FLASH_SCRIPT` in `_document`; `?ui=<id>` forces and saves one) selects a block of `--ui-*` variables; the shared classes (`ui-panel`, `ui-btn`, `ui-group`, `ui-toggle`, `ui-seg`, `ui-field`, `ui-check`) read only those. **Build controls from the React components in `components/ui/` (`Button`, `LinkButton`, `Select`, `TextInput`, `Checkbox`, `Toggle`, `SegmentedControl`, `Panel`, `Group`, and `Field` for the caption above any control: never write a screen's own label style), never a raw `<select>`/`<input>`/styled `<button>`, and use `var(--ui-*)` instead of literal colours in page SCSS; a new kind of control goes in `components/ui/` + `_ui-kit.scss` + `ThemeSample.tsx` and `pages/ui-lab.tsx` (so the lab shows it in every state).** A test fails on a raw `<select>`/`<input>` in the themed screens. **Animated icons** (`components/ui/AnimatedIcon.tsx`, registry `animated-icons.ts`, frames in `public/images/ui/animated/<id>/NNN.png`, 96 px, ~1.4 MB for all 22; the Basic Shapes packs, tinted by `currentColor`): `<AnimatedIcon name on />` plays forward when `on` turns true and back when false (`hideWhenOff`: drawn in on, faded out off, for things that come and go), `loop` spins; frames are decoded once and painted on a canvas (a per-frame CSS `mask-image` swap flashed; keep it off React state); reduced-motion shows the last frame. Off draws nothing (the first frames of most icons are stray marks); each icon is sized by its resting last frame (the `spinner` ones by all frames) and fitted without stretching, because the sequences differ in canvas size and padding (Parallel Dots is 177 x 49). The `Checkbox` tick is the cross-into-checkmark one. `/ui-lab` has a gallery. The kit themes' toggle is split into track and knob images (`toggle_track_on/off`, `toggle_knob_on/off` in each theme's art folder, cut from the kit's `toggle_on/off` so the knob can slide); a new kit theme needs those four too. A row of form controls (filters, toolbars) gets `ui-controls`: every control in it is `--ui-control-h` tall and the row keeps that height, so a button that appears (Clear filters) never shifts the layout. Screens keep layout in their own SCSS. Themed: site base, bottom nav, markdown pages, profile, collection, deck builder, heroes viewer, the `/play` menu/pickers/dialogs. Not themed (on purpose, for now): cards, minions, heroes, the board itself (End turn, log, deck list), the dev labs' sliders, and the old Sidebar/Header/store/cards pages.
- Themes now: `classic` (the old look, default), `emberhold`, `frostforged` (art in `public/images/ui/<id>/`, sounds in `public/sounds/emberhold/`). A theme is an entry in `UI_THEMES` + a block in `_themes.scss` (written as classic + overrides); a test checks they match. `/ui-lab` shows all side by side. Menu sounds (`ui-sfx.ts`) play for clicks inside any `[data-ui-sfx]` area and share the Sound switch. The profile's "colour theme" (`THEMES` in `profile.ts`) is a different thing: the player's side colour.
